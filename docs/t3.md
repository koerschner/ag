# T3 Code as Ag's UI

Status: **migrating** (started 2026-10-07). [T3 Code](https://github.com/pingdotgg/t3code) (MIT) replaces
ag-dash and the tmux tabs as the place sessions live: desktop app, web, and iOS, all on one server.
Everything else in Ag stays: the ag-inbox and its capture paths, the ag-tickler, routines, `ag-mac`, computer
use, secrets, MCP.

## How it fits

| Piece | Where |
|---|---|
| Server | `ag-t3.service` on the session host: `t3 serve` on 127.0.0.1:3773, data in `~/.t3` → `/data/t3` (persistent volume). Published as `https://ag.<tailnet>.ts.net` (port 443 on svc:ag; `ag-svc`). Runs **Nathan's fork** `koerschner/t3code` (`~/t3code`, read its `FORK.md`): `ag/ship` builds, gates and deploys it, and the `t3-upstream-sync` routine merges upstream nightly. Never `t3 update` (that replaces the fork with upstream). |
| Mac app | **T3 Code (Ag)** on the client Mac: the fork's Electron app, built on ag-mac and installed by `~/t3code/ag/build-mac` (run by `ag/ship` when a change can reach it). No update feed, so it stays on the fork. Upstream's T3 Code (Nightly) is retired to `/Applications/Retired/`. A second copy runs on **ag-mac**, paired to the same server (pairing label `ag-mac T3 Code (Ag)`; re-pair with `t3 auth pairing create --base-url https://ag.<tailnet>.ts.net`, the link piped into ag-mac's clipboard, then Settings → Connections → Add environment), so agents test the Mac app (quick entry, windows, screenshots) on ag-mac's screen and never drive the client's desktop for it. |
| Phone | Upstream's iOS app (TestFlight), paired with the server; it gets the fork's server features, not its UI. |
| Agent | Pi, with the real `~/.pi/agent` (AGENTS.md, skills, extensions, models). ag's tmux-only extensions switch themselves off without `AG_MUX=1`. A T3 thread *is* a Pi session file. |
| Bridge | `ag-t3` (bin): `new`, `send`, `thread`, `threads`, `import`, `refresh`, `link`, `delete`, `setup`, `doctor`. Talks to T3's WebSocket RPC (`orchestration.dispatchCommand`) with an admin token in `~/.config/ag/t3.token`. |
| Mode switch | `AG_UI=t3` in `~/ag-personal/env`. Then the ag-inbox makes captures T3 threads (Jev's follow-on matching runs over T3 threads), `ag send`/`ag report` (aglib `prompt`) queue into the session's T3 thread, and the ag-tickler fires into the deferring session's thread (or a new one). Restart `ag-inbox.service` after changing it. |

## Pairing a replacement iPhone

Connect the phone to the same Tailscale network, then open T3's Settings → Environments → Add environment.
From the Mac running Mirroring, capture a fresh one-time credential from the session host into a private
temporary file, then copy only the credential to that Mac's clipboard through the authorized screen workflow:

```sh
pairing_file=$(mktemp -t t3-phone-pairing)
chmod 600 "$pairing_file"
printf 'Pairing file path: %s\n' "$pairing_file"
ssh ag-engine 't3 auth pairing create --label "phone T3" --ttl 20m --json' > "$pairing_file"
jq -rj '.credential' "$pairing_file" | pbcopy
```

Record the printed path (it is not a secret), so cleanup works even in a later shell. Never print the JSON
or credential into a tool result. Paste the clipboard into the phone's **Code** field.
Enter **`ag.<tailnet>.ts.net` without `https://`** in Address and the credential in Code. The native iOS
build tested during replacement-phone setup rejected a scheme-prefixed address with “Pairing URL is
invalid”; the bare hostname paired successfully over HTTPS. T3 Connect sign-in is not needed.

For iPhone Mirroring, enter the fields manually; the phone camera is unavailable from the Mac. If simulated
keystrokes drop characters, use the phone's text-editing **Paste** menu and verify the address. Keep the
credential out of chat, screenshots, and autosaving editors. Verify **ag-engine · Connected**, open an
existing conversation. If pairing fails or is abandoned, read the non-secret `id` from the private JSON
and run `t3 auth pairing revoke <id>` on the session host before deleting the file. `t3 auth pairing list`
can also find an unconsumed credential without revealing its secret. Whatever the result, remove the file
at the recorded path and clear the transfer clipboard (`printf '' | pbcopy`). Do not rely on shell
variables surviving between separate tool calls.

## Migrating sessions

`ag-t3 import --all-open` turns every open ag session into a T3 thread:

- `thread.create` with `importedNativeThread {driver: pi, nativeId: <session file>}` binds the thread to the
  existing Pi session, so the next message resumes it natively (full context, tools and all).
- T3 doesn't read a Pi file's history into its view, so the active branch's user turns and assistant replies are
  written as v1 transcript rows (`projection_thread_messages` + `orchestration_v2_legacy_imports`); T3's v1
  importer hydrates them the first time the thread is opened. `ag-t3 refresh` re-snapshots threads not yet opened.
- Title, pin (and pin order) carry over. Inbox / Needs you have no T3 equivalent yet (T3 refuses mark-unread on a
  thread without a run).

Never let a session run in both places: once a session is in T3, close its tmux tab (or let it finish first). `ag-t3 import` skips a Pi file still held by a live or sleeping tmux tab. Closed sessions can be imported from their Pi file path; the tickler imports a deferring session on demand before sending its wake-up. If the file is missing, the reminder still fires in a new T3 thread with a log warning about lost context. If its tmux tab is busy or sleeping, the tickler forks a Pi tab instead, preserving the session context. Import waiting tickler sessions ahead of migration so their history is already visible.

## Model selection safety

T3 has two Pi lanes, both on the same **TrueFoundry** models; they differ only in where Pi stores the session. A thread's first message decides which one it runs in ("Off the record" below): only FreeTime work syncs.

- **`pi`** ("Pi", the default instance): synced. Sessions under `~/.pi`, which Nessie syncs.
- **`piPrivate`** ("Pi · private (unsynced)"): off the record. Same Pi, config, extensions and models, but the instance sets `PI_CODING_AGENT_SESSION_DIR=~/private-chat/pi-sessions` (T3 never passes a session dir, so the environment decides; `ag-pi-private` uses the same folder), so Nessie never sees its sessions.

T3 shows Pi's entire model catalog (about 515 models: hundreds of personal OpenRouter models and the direct `anthropic` and `openai-codex` logins next to the TrueFoundry ones) for every Pi instance, so a composer can default to a model outside TrueFoundry. On 2026-10-11 new `pi` threads picked `anthropic/claude-opus-5-5` (whose OAuth refresh failed) and `openai-codex/gpt-6-astra`, and a T3 client kept writing such selections back. Three layers keep every thread on TrueFoundry:

- **Server-side model preferences.** Since upstream #16816, T3 keeps favorites, hidden models and model order in server settings and syncs them to every client (`favorites`, `providerModelPreferences.<instance>.{hiddenModels,modelOrder}` in `~/.t3/userdata/settings.json`). `ag-t3 setup` hides every model outside TrueFoundry in both lanes' pickers (the private lane's mirrors the synced lane's), puts TrueFoundry Opus first and favorites it. New models from catalog updates stay visible until setup runs again; `doctor` warns about them.
- **Pi's extensions.** In every session (either lane, tmux sessions, routines), `truefoundry-only` switches a pick outside TrueFoundry (the direct `anthropic` and `openai-codex` logins, OpenRouter) to the TrueFoundry copy of the same model (`anthropic/claude-opus-5-5` and OpenRouter's `anthropic/claude-opus-5.5` → `truefoundry/anthropic-primary/claude-opus-5-5`, `openai-codex/gpt-6-astra` → `truefoundry-openai/gpt-6-astra`), else to TrueFoundry Opus. T3 doesn't reflect the switch in its composer, which is why hiding comes first.
- **Thread selections.** `ag-t3 doctor` flags threads whose saved model is outside TrueFoundry; fix them with `t3_thread_configure` (or the composer) using the TrueFoundry copy, e.g. `truefoundry-chat/fireworks-group/glm-5p3` for GLM. Don't change the model of a thread that is mid-run (see below).

**Moving a thread between lanes.** `ag-t3 send --instance piPrivate --model truefoundry/anthropic-primary/claude-opus-5-5 [--thinking max] <thread> <text>` queues a message that carries the new selection. T3 plans the switch when that message's run starts, after any active run (`t3_thread_configure` to another instance on a running thread detaches its live session at once, cutting the turn off). It starts a new native Pi session in the target lane with T3's context handoff: a digest of the thread capped at about 16,000 tokens (`T3CODE_CONTEXT_HANDOFF_TOKEN_CAP`); the full history stays readable with `t3_thread_read`. The earlier transcript stays where it was (already synced, if it began in the `pi` lane). A model change within a lane keeps the same Pi session.

**Off the record.** `ag private [session]` does that move for a session's thread, keeping its model. The fork's server also asks Ag's `lane` rules (ag-rules) before T3 starts every message the user sends and the first message of every thread, whichever way it starts (composer and quick entry launch threads, `ag-t3 new` creates them, agents launch them over MCP; `apps/server/src/ag/lane.ts`). A rule answers `{ lane: "private" }` or `{ lane: "synced" }`, and private wins when they disagree; the message, and the thread from then on, moves to that lane, keeping its model (one outside TrueFoundry becomes Opus 5.5, keeping the thinking level), queued behind a running turn rather than steered into it. The user's `freetime-sync` rule starts every thread off the record: Jev reads its first message, and only FreeTime work moves to the synced lane (unclear messages and Jev failures stay private). Their `off-the-record` rule moves a thread private whenever they say "off the record". A thread stays in its lane until a rule or a model pick from the other lane moves it; to sync a thread Jev kept private, pick its model under "Pi" in the composer. Routines (`pi -p`) don't go through T3, so they always sync.

**OpenRouter Claude models need a `models.json` entry.** `~/ag-personal/pi-models.json` overrides the `openrouter` provider with OpenRouter's OpenAI-compatible `/api/v1` endpoint (for Fable 5), and pi applies that base URL to catalog models that use the Anthropic API, so every call 404s. Give such a model its own entry with `api: anthropic-messages` and `baseUrl: https://openrouter.ai/api` (Opus 5.5 has one). Haiku 5.5 is also on TrueFoundry (`truefoundry/anthropic-primary/claude-haiku-5-5`).

`ag-t3 setup` enables both Pi provider instances (`providerInstances.pi` and `providerInstances.piPrivate`: driver `pi`, Ag's `~/.local/bin/pi`, the private one with its session-dir environment), configures a non-Anthropic title-generation model, applies the model preferences above, then runs `doctor`; bootstrap calls it on every host setup, and it's safe to rerun after an upstream sync. `ag-t3 doctor` checks the live Pi catalog, the configured provider instance, visible non-TrueFoundry models, expired OAuth access tokens and thread selections, reporting rather than silently substituting. `ag-t3 new --model` refuses models outside TrueFoundry.
