## Prompt conventions (Nathan's shorthand)

- **[Square brackets] are meta notes.** Text Nathan puts in square brackets in a prompt is about the system itself (instructions for these AGENTS.md sources, the ag and dotfiles repos, how agents should behave), not about the work at hand. Apply them to the system (usually a new rule in `agents.md/`, rebuilt and pushed per "Machine setup lives in git") and keep doing the actual task.
- **"Split out" = new Inbox session that reports back.** Open a new session in the Inbox workspace with a self-contained prompt for that work (see "Helper sessions and links" under Herdr), and tell Nathan the link. The prompt must tell the new session to report back when it's done or blocked. Find the originating pane by its Pi session file, because pane IDs change when a tab is filed into another workspace: `herdr pane list | jq -r --arg f "$PI_SESSION_FILE" '.result.panes[]|select(.agent_session.value==$f)|.pane_id'`, then `herdr agent prompt <pane> "Report from split-out session '<label>': …"`. If that pane is gone or busy, it sends the report to the ag inbox instead. `$HERDR_PANE_ID`/`$HERDR_TAB_ID` in your own env can also be stale after filing; look yourself up the same way.
- **Link every wake-up.** Whenever another session is going to wake up or report back to yours (a split-out, a helper you prompted, an access session, a tickler item), put its clickable link in your reply to Nathan (`herdr-link <tab>`, or its `http://ag:7376/<session id>` board link), so he can jump to whatever is going to resume the work. For a tickler item that resumes your own session, give its id and what it's waiting on. When a report or wake-up arrives, link back to the session it came from.
- **"Merge session A into this one" = absorb A, then retire it.** Read A's transcript (user and assistant text from its `.jsonl`; the path shows in `herdr pane list` as `.agent_session.value`, or on a hibernated tab's screen) so its context and decisions carry on here. Then mark A's end: append to A's `.jsonl` (only while its Pi isn't running, e.g. hibernated or exited) a `custom_message` entry (`customType: "merged-into"`, `display: true`, `parentId` = A's last entry id) that names this session's file and what carried over, plus a `session_info` entry renaming it `[merged → <this tab label>] <old name>`. Close A's tab (`herdr tab close`), but keep its session file as the record. In your reply, say what was merged and summarize the context you picked up.
- **Pay for infra with the Ramp card.** Nathan's work Ramp card is in 1Password (limit $10K/month). Use it for all infrastructure and service purchases unless he says otherwise. It isn't in the vault `op-ag` can read; if you can't reach it programmatically, ask him to share the item into the canonical arcade.school vault. Never type card numbers into chat or logs.
- **"Friction" = run the `fix-friction` skill.** When Nathan says "friction" (or runs `/fix-friction`), he had to step in for something Ag should handle itself. Load the `fix-friction` skill: it spins out a Fix Friction session that removes the root cause at the core of Ag and logs it in `friction.md` in dotfiles, while you carry on with the task.
- **"ag debug" = run the `ag-debug` skill.** When Nathan says "ag debug" (any casing, anywhere in a message, or `/ag-debug`), something in Ag itself is broken or misbehaving. Load the `ag-debug` skill: extract the meta issue (what in Ag went wrong, not the task) and spin out an Ag Debug session that root-causes and fixes it and reports back, while you carry on with the task.
