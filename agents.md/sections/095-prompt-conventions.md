## Prompt conventions (Nathan's shorthand)

- **[Square brackets] = spin out a new session.** Never handle bracketed text inline: send each bracketed note to its own session with `ag spawn "<the note, made self-contained with the context it needs>"`, then carry on with the rest of the prompt. Brackets are often about the system itself (these AGENTS.md sources, the ag and dotfiles repos, how agents behave); when one is, say so in the spawned prompt. Give Nathan the new session's link.
- **"Split out" = new Inbox session that reports back.** Run `ag spawn "<self-contained prompt>"` (or `ag spawn -f prompt.md`): it opens a new Inbox session through the ag inbox and appends a report-back footer naming your session, then prints the new tab and its AG Dash link; give Nathan that link. The new session reports with `ag report "…"`, which finds your session fresh (waking it if hibernated) and falls back to the ag inbox if it's gone. To find yourself, use `ag me`, never `$AG_TAB_ID`/`$AG_WORKSPACE_ID` (stale after filing).
- **Link every wake-up.** Whenever another session is going to wake up or report back to yours (a split-out, a helper you prompted, an access session, a tickler item), put its clickable link in your reply to Nathan (`ag link <session>`; `ag link` alone is your own), so he can jump to whatever is going to resume the work. For a tickler item that resumes your own session, give its id and what it's waiting on. When a report or wake-up arrives, link back to the session it came from.
- **"Merge session A into this one" = absorb A, then retire it.** Run `ag merge <A>` (A = session id, tab, AG Dash link or label; several at once is fine). It prints A's transcript so its context and decisions carry on here, closes A's tab, and marks A's session file (a `merged-into` note naming this session plus a `[merged → <this tab>] <old name>` rename), keeping the file as the record. `--note "…"` records what carried over; `--into B` merges into another session instead (B is told to read A with `ag read`). In your reply, say what was merged and summarize the context you picked up.
- **Pay for infra with the Ramp card.** Nathan's work Ramp card is in 1Password (limit $10K/month). Use it for all infrastructure and service purchases unless he says otherwise. It isn't in the vault `op-ag` can read; if you can't reach it programmatically, ask him to share the item into the canonical arcade.school vault. Never type card numbers into chat or logs.
- **"Friction" = run the `fix-friction` skill.** When Nathan says "friction" (or runs `/fix-friction`), he had to step in for something Ag should handle itself. Load the `fix-friction` skill: it spins out a Fix Friction session that removes the root cause at the core of Ag and logs it in `friction.md` in dotfiles, while you carry on with the task.
- **"ag debug" = run the `ag-debug` skill.** When Nathan says "ag debug" (any casing, anywhere in a message, or `/ag-debug`), something in Ag itself is broken or misbehaving. Load the `ag-debug` skill: extract the meta issue (what in Ag went wrong, not the task) and spin out an Ag Debug session that root-causes and fixes it and reports back, while you carry on with the task.
