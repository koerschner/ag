## GTD model

Ag's session layer (tmux via `ag-mux` on ag-engine) is the user's GTD system: every open session (tab) is one item, in one flat list (there are no workspaces or projects). The **Inbox** is a state, not a place: a session is in the Inbox until the user first replies to it (ag-dash's Inbox view, `ag ls --inbox`). New sessions captured from anywhere via the ag-inbox (`http://ag:7373/prompt`; both Command keys on the Mac, the Action Button on the phone) start there, and so do sessions agents spin out (see "Helper sessions and links" under Sessions). A capture that is clearly new context for an already-open session (Jev decides) is delivered into that session instead, under a `kind="follow"` origin tag: treat it as a reply from the user, and if it doesn't belong say so and suggest where it goes. When the match is plausible but unsure, the new Inbox session's prompt names the likely session (a `kind="hint"` tag): if it fits on inspection, forward it there with `ag send <session> "…"` (include what you learned), link it, and close the Inbox session (`ag close`) without asking; ask only when it's genuinely ambiguous. Be aggressive about consolidating in general: when a session or message clearly belongs with another open session, forward or merge it (see "Merge session A into this one") rather than keeping parallel threads, and tell the user what you did. Deferred items go in the ag-tickler (the `ag-tickler` tool), which reopens them as new sessions when they're due. Work that should resume once the user is back at their Mac ("next time I'm on the client", or it needs them physically: a phone press, a click, a login) goes in the ag-tickler with `when: "online"` instead of a time: it fires, forked from your conversation, on their next arrival at the client (sustained activity, detected by `ag-presence` on ag-mac; see the ag README). To check whether they're at their Mac right now, run `ag-presence`.

**Defer-only sessions close themselves.** When a session exists just to defer something (the user asks you to ag-tickler/defer a task and nothing else is left to do in it), once the ag-tickler item(s) are scheduled: send the user a one-line confirmation through the notification channel (`ag-text "⏰ Deferred: <title> → <local date/time>"`; one line per item), then close your own tab with `ag close` as the last step. The ag-tickler forks this conversation when it fires, so nothing is lost. Keep the tab open instead if you asked the user a question they haven't answered yet, or if there's other work left in the session.

**Waiting always wakes up.** A session in ag-dash's **Waiting for** column must have a live ag-tickler item that will wake it; nothing sits there silently. When the user asks you to put a session in waiting (or you're waiting on a person, CI, a deploy, a reply), schedule the wake-up yourself and choose the interval: a `waitingFor` item for a person (first check-in usually the next business day in their afternoon; it backs off and nudges on each attempt), or `when: "check"` with a cheap shell check plus an `expires` for a machine or programmatic signal. If you can't check programmatically (e.g. no API for the mailbox), the woken session checks by computer use. Never follow up with outside parties (counsel, partners) on the user's behalf without their OK; draft the follow-up for them instead. Marking a card waiting by hand in ag-dash doesn't count until the session has scheduled its wake-up.

**Waiting on the user is Needs you, not Waiting for.** When the thing you're waiting on is the user themselves (you asked them to sign in, click, approve, or answer), the session belongs in **Needs you**. You may still schedule a `check` wake-up so you resume the moment they're done, but pass `needsUser: true` to the ag-tickler so ag-dash keeps the card in Needs you. Never use `waitingFor` for the user.

**Prompt origins.** Prompts Ag injects (ag-inbox follow-ons and hints, `ag spawn`, `ag report`, the ag-tickler, ag-rules, phone review comments, AG Dash) carry their routing context in an `<ag-origin kind=… label=… title=… sid=…>note</ag-origin>` tag instead of prose. Read the note: it's addressed to you. The UIs hide the tag and show the user a small chip ("↩ Report from “Fix Ag Inbox”"), so what they read is only the message. When you build a prompt for another session yourself, put routing context in a tag the same way (`origin_tag` in aglib.py, `originTag` in pi/dot-pi/agent/extensions/ag-origin.ts) and keep the visible text to the message itself.
