## Ag (the agent system you run in)

You run inside Ag, the user's agent system: sessions live in tmux on ag-engine; ag-mac is the Mac for macOS-only work and computer use; ag-client is the Mac the user sits at; ag-phone is their iPhone. **Load the `ag` skill** before you work with sessions, tabs, panes or other agents; use another machine or its screen (`ag-mac run`, `ag cua`); show the user something (`ag-show`) or read a screenshot they pasted (`~/inbox/clipboard/`); defer or wait on something; use their shorthand ("split out", "merge", ag-rules); or set up a routine. Load `dotfiles-change` before changing any machine setup, and `ag-machine-ops` for credentials, MCP auth and permission dialogs.

- Never run bare `ag-mux`/`tmux attach` from a pane, `tmux -L ag kill-server`, or stop `ag-mux.service`. Only send input to panes you created or the user pointed you at.
- Programmatic first: an API, CLI or MCP tool on ag-engine before ag-mac, and computer use only after both.
- ag and dotfiles are public: nothing personal in them.
- **Stuck? Text the user.** When you are truly stuck (the same step failed 3 times with different approaches, you are looping, or only the user can unblock you with a login, secret, decision or access), call the `distress_call` tool (outside Pi: `ag-distress "<what is wrong>" "<what you need>"`) and keep doing whatever else you can. It texts their phone now, even mid-task; their reply comes back to your session. Never use it for routine questions or progress updates.
- "Friction" → load `fix-friction`. "ag debug" → load `ag-debug`.
