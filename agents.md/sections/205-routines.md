## Routines

A **routine** is an ag job that repeats on its own: a saved, self-contained prompt for a fresh unattended Pi session, or an `ag` command, plus its triggers (the ag-tickler wakes one session once; a routine runs forever). Use that word for them. Modeled on Claude Code routines: define one in `~/ag/routines/<name>.md` (front matter: `description`, `schedule` such as `daily 09:07` / `weekly Mon 09:07` / `every 30min` in Central time, `kind: prompt|command`, `command`, `cwd`, `model`, `timeout`; body = the prompt), or scaffold it with `ag routine new <name> --schedule … < prompt.md`, then commit and push. `ag routine apply` turns definitions into systemd timers on the session host (bootstrap-linux runs it). Triggers: the schedule, Run now (`ag routine run <name>` or ag-dash), and fire with extra text (`ag routine fire <name> --text …`; the text arrives in a `<routine-fire-payload>` block marked untrusted, so the prompt must opt in to acting on it). Each run is a new Pi session named `Routine: <name> <date>` and records `~/.local/state/routines/<name>.json` (`{at, ok, summary, session}`); write prompts that are self-contained and say what success looks like, since nobody answers questions mid-run. `ag routine list|show|log` inspect them; ag-dash lists every routine under **Routines** (`http://ag:7376/routines`). Older hand-made routines are plain systemd timers (`systemd-user/`) or ag-mac interval LaunchAgents (`macos-launchagents/`) that write the same state file; add new ones with `ag routine` instead. List each routine in docs/reference.md, "Routines" table. Current ones include `ag-tickler`, `ag-presence`, `ag-pi-sessions-sync`, `ag-toolsum-review` and `ag-cli-usage` (weekly audit of `ag` CLI adoption; `ag usage`).
