- **link (20%)**: about half the "errors" are other commands in the same line. The real ones: `ag link`
  only resolves *open* sessions, so a closed session's id or label fails ("no open session matches"), even
  though ag-dash links work for closed sessions. Also fails for tabs with no Pi session (expected).
- **peek (17%)**: almost all noise from other commands in the call (ag-mux errors, a dev server's own
  output containing "not found"); one real case was peeking a tab just closed.

Together, pane-run + pane-read + dev-tab + the label lookups are ~300 calls: one missing verb for the
dev-process lifecycle (open a labeled tab in a cwd, run a command, read its output, wait for a URL/regex,
close it). The AGENTS.md "Dev processes" rule says what to do but only `ag-mux --skill` says how.

## Changes this week

- Catalog: new `pane-run` pattern (`ag-mux pane run|send-text|send-keys`, `tmux -L ag send-keys`);
  `dev-tab` += `tmux -L ag new-window`; `mux-snapshot` += `ag-mux pane list`.
- Spun out: build an `ag dev` verb for dev-process tabs (open/run/read/wait/close by label) and switch the
  "Dev processes" instructions to it.
- Noted, not acted on: `ag link` should resolve closed sessions (next run's candidate if still erroring).
